# TC-INSTK-1-08: OpenAPI v2 document describes inStock; v1 document does not

## Why

- API consumers discover the filter from the OpenAPI document; the product owner asked for it in v2 and for v1 to stay unchanged. Functional, because the document is generated by the running host (`/openapi/v{n}.json`), as the Ordering contract tests already read it.

## Preconditions

- Catalog functional fixture running (data does not matter).

## Steps

1. Anonymous `GET /openapi/v2.json`.
2. Anonymous `GET /openapi/v1.json`.

## Expected result

- Both answer 200 with a JSON OpenAPI document.
- In the v2 document, `paths["/api/catalog/items"].get.parameters` has an entry with `name` `inStock`, `in` `query`, not `required`, and a boolean schema.
- In the v1 document, `paths["/api/catalog/items"].get.parameters` has no entry named `inStock`.
